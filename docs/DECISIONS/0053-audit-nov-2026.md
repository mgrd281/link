# 0053 — Product audit, November 2026: what was measured, fixed and left

**Context.** The founder asked for a complete, evidence-based improvement of the existing product: design,
UX, layout, motion, accessibility, performance and brand consistency. Two brand rules came with the request:
the palette starts from #00454C, #00565F and white, and no orange. The request also mentions a recording of a
real user session; none was attached, so this audit rests on the product itself.

**Method.** Measured before changing anything, on the production build (`next start`):

- full-page screenshots of the homepage, templates, sign-up, login and a creator page at 320, 375, 390, 768,
  1024, 1440 and 1920 px, with checks per page: horizontal overflow, elements outside the screen, targets
  under 24 px (WCAG 2.5.8), console errors;
- the app journey (sign-up with the code, welcome flow, Home, Page, Add and Profile sheets, Design, Stats,
  Settings, View my page) on a phone and a computer, with the `linkyo-ux-audit` script (its sign-up step was
  brought up to date for the code step);
- Lighthouse 13 (simulated mobile) on four pages;
- section headings measured across the homepage (all 28 px on phones and 36 px on computers, same weight and
  tracking; the FAQ heading sits beside its list on purpose, the last call to action is larger on purpose).

**What was found and fixed** (most impact first):

| # | Finding | Evidence | Fix |
|---|---|---|---|
| 1 | The homepage loaded the block schemas (Zod, 33 KB gzipped) for the address field, and the playground's page renderer with the whole picture catalogue, before anyone saw them | Lighthouse performance 74, blocking time 250 ms | Address rules without Zod (`@linkyo/blocks/rules`, `/detect`); the playground's phone is its own chunk, loaded one screen before it is in view; swatch colors resolved on the server; the theme engine loads on the first custom color; platform glyphs and image sizes moved to a light module (`shared/platforms.tsx`) |
| 2 | Horizontal scrolling at 1024 px | 27 px overflow from the hero deck's side cards | The deck is clipped up to 1280 px; 0 overflow at all widths from 320 to 1920 px |
| 3 | The templates page's largest picture loaded lazily, without priority | Lighthouse "LCP request discovery" failed | The first two cards load first, with high priority |
| 4 | On "View my page" the owner's bar sat on the privacy notice's buttons | Screenshots, phone and computer | While the notice is open the bar waits at the top; once decided it returns to the bottom (`usePrivacyNoticeOpen`) |
| 5 | Orange in Linkyo's own interface | "Sample data" badges, warning tone | Sample data is information, not a warning: neutral badges. The warning scale is gold (hue 44–46°, was 28–34°); its text tone is darker and reads better: 6.9:1 on white (was 5.4:1) |
| 6 | The demo's two German buttons wrapped inside themselves on phones | Screenshot at 390 px | Labels stay on one line ("Wiederholen", "Leeren"); the pair moves below the caption when needed |
| 7 | The welcome flow put the address in the name field ("ux-mobile-mwotzv5r") | Screenshot | New pages start with a name made from a chosen address ("mila-aurel" → "Mila Aurel"); a neutral address leaves the field empty, so the address follows the name typed |
| 8 | Footer links 20 px high | Target check | 28 px rows, same rhythm |

**Results** (same build, same tools):

| Page | Performance | LCP | Blocking time | Weight |
|---|---|---|---|---|
| Homepage | 74 → 83 | 5.6 → 4.6 s | 250 → 100 ms | 1136 → 1006 KiB |
| Templates | 57 → 61 | 6.3 → 5.7 s | 820 → 670 ms | 1363 → 1345 KiB |
| Creator page | 75 → 81 | 4.8 → 5.0 s | 310 → 90 ms | 858 → 844 KiB |
| Sign-up | 97 → 97 | 1.4 s | 190 → 210 ms | 635 → 595 KiB |

On the live site (Vercel, the same Lighthouse run from this machine): homepage 81 (LCP 3.3 s), templates 59,
creator page 87 (LCP 3.8 s). `/robots.txt` answered with an HTML error page; it now allows crawling, so the
pages' own `noindex` is read (indexing does not change).

Accessibility and best practices stay at 100 on all four; CLS stays at or under 0.02. Targets under 24 px went
from 8–9 per page to the skip link only (it appears on focus and is exempt). No console errors. These are
laboratory numbers on a local machine; there is no real-user data yet.

**Left open, and why.**

- **SEO 60–63** comes from one line: every page says `noindex, nofollow`. That is a launch decision for the
  founder (the concept pages of well-known people are part of it), not a fix.
- **Templates performance (61).** The page renders all 70+ examples and the moving wall at once (1.15 MB of
  HTML). Showing a first set and the rest on demand would help most; it changes how the gallery behaves, so it
  is proposed, not done.
- **LCP on the homepage (4.6 s simulated)** is the hero deck's first picture, painted after the page's
  JavaScript runs; the remaining cost is mostly React and Next.js themselves.
- **The session recording** was not attached; its findings would come on top of these.

**Status.** Applied. Tests: unit tests for the address rules and first names, an e2e test for the owner's bar
and the privacy notice, the playground tests (now with the phone loaded on demand), and the full suite.
